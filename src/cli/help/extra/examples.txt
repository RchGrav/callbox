backmux help examples - more ways to use Backmux

For the main workflows, start with help tui, share, agents, messaging, or
service. The examples below assume the named programs, files, and project
scripts already exist. Replace app-specific prompts with your app's output.

TEST A TERMINAL APP
    backmux -dt --size 100 30 --name app -- ./my-tui
    backmux wait app --match "Main menu" --timeout 5000
    backmux send app 2 --enter
    backmux wait app --match "Saved" --timeout 5000 ||
        backmux peek app --image fail.png
    backmux end app
    backmux purge app

RUN A DEVELOPMENT SERVER
    backmux -d --name api -- npm run dev
    backmux logs api -f
    # Ctrl-C stops following the log.
    backmux end api
    backmux api
    # Later, stop it and release its name.
    backmux end api
    backmux purge api

KEEP A VM RUNNING
    backmux -d --name vm -- qemu-system-x86_64 -m 4G disk.qcow2
    backmux logs vm -n 50
    backmux stats vm --no-stream
    backmux end vm
    backmux purge vm

  stats reports process-group CPU and memory on Linux. Backmux keeps the
  process running; VM disks and the VM's own shutdown procedure remain
  QEMU's responsibility.

COLLECT A LONG JOB'S RESULT
    backmux -dw --name backup -- ./backup.sh
    code=$(backmux wait backup)
    backmux logs backup -n 50
    backmux purge backup
    exit "$code"

DRIVE SEVERAL SERIAL CONSOLES
    for i in 1 2 3 4; do
        backmux -dt --name node$i -- qemu-system-x86_64 -nographic -m 512M \
            -drive file=node$i.qcow2 -nic user,model=virtio
    done
    backmux wait node3 --match "login:" --timeout 120000
    backmux send node3 root --enter
    backmux peek node3
    backmux attach node3

  This assumes each disk boots a serial console and accepts that login.
  Ctrl-P Ctrl-Q detaches. Shut down the guests normally before removing
  their ended processes with backmux purge.
