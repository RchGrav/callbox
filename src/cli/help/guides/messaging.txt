backmux help messaging - send messages and receive replies

Send work to a terminal agent through its input console and receive reports
in a managed process or inbox. The sender needs command execution access;
the receiving agent needs a terminal or pipe-input console.

PREPARE A RECEIVER
  This example uses an installed, configured Codex harness:

    backmux detach --name reviewer codex
    backmux set reviewer agent
    backmux wait reviewer --idle 1000
    backmux peek reviewer

  Check that its prompt is ready. If it is already running as a process, use
  that process's name instead (backmux set NAME agent if it was started as a
  plain process). backmux list shows running processes, not inboxes.

SEND FROM A HARNESS OUTSIDE BACKMUX
  Run this in your existing harness's command tool:

    backmux msg reviewer "Review the current diff and reply with findings."

  The first send prints your generated inbox name on stderr. reviewer sees
  a header with that name and the command to reply to it. It answers with
  backmux msg NAME "...", using the actual name from the header.

WAIT FOR A REPLY OR FOLLOW THE CONVERSATION
  In the same harness, wait for one unread message:

    backmux inbox --wait --timeout 600000

  To keep receiving messages, run a monitor as a long-running command in
  your harness's background command facility, then wait on that command
  using the harness's own tools:

    backmux monitor --timeout 600000

  monitor prints unread messages, then new ones, flushing each to stdout.
  In a separate terminal use backmux monitor NAME with the inbox name from
  the first send; a different harness can have a different default inbox.
  Ctrl-C stops the monitor. backmux inbox shows retained history and marks
  it read. These readers share unread progress, so use one reader at a time
  when you want to consume each reply once. inbox --monitor also works.

  For a single blocking send-and-wait operation:

    backmux msg reviewer "Report your review status." \
      --wait-reply --timeout 600000

  This waits for the first new message in your inbox after sending, from
  any sender. It does not match replies to requests. Read the sender and
  text before treating a message as the answer to a particular task.

UNDERSTAND WHERE A MESSAGE GOES
  Terminal and pipe-input processes receive message text as program input,
  followed by Enter by default. The agent setting adds a sender/reply header;
  without it, no header is added. set NAME agent and unset NAME agent change
  the format for subsequent messages. Address messages to a person by their
  chat name; the messages appear in their chat window (Ctrl-Space c).
  server processes have no input console and refuse messages. Backmux delivers
  input; it does not manage a harness's work queue.

  An outside inbox is created on first send, not by monitor. Its name
  expires after an hour without use; individual messages expire one hour
  after delivery. With no timeout, wait for a message or inbox expiry.
  A timeout exits 7; inbox expiry exits 8.
  backmux wait is different: it waits for a process's screen or process exit.

  When the reviewer is no longer needed: backmux end reviewer, then
  backmux purge reviewer. This removes the process, not your outside inbox.
