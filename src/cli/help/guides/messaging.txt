callbox help messaging - message agents, inside or outside callbox

USE THIS WHEN
  Agents need to talk: to hand off work, report back, or ask. They can run
  in different harnesses (Claude Code, Codex, opencode, ...). Anything
  that can run a shell command can send; a call can receive.

EXAMPLE: BOTH AGENTS RUN INSIDE CALLBOX
    callbox -it --name lead claude          # you work with lead
    callbox -dt --name reviewer codex       # lead starts a second agent
    callbox msg reviewer "review the diff in src/net.c"     # from lead

  reviewer sees the text in its prompt, after a header:

    [msg from lead; reply: callbox msg lead "..."] review the diff in ...

  It answers with callbox msg lead "...", typed into lead's prompt.

EXAMPLE: YOUR HARNESS RUNS OUTSIDE CALLBOX
  An agent callbox did not start (Claude Code in a plain terminal, a
  script) gets a name of its own with its first message, and an inbox for
  the replies. The receiver sees an ordinary header and answers as usual.

    callbox msg reviewer "review src/net.c" --wait-reply --timeout 600000

  That sends, then blocks until the first reply and prints it:

    [14:02 from reviewer] two problems: the retry loop never ...

  Or send, keep working, and read the replies when you choose:

    callbox msg reviewer "review src/net.c"
    callbox inbox --wait                    # the next unread reply
    callbox inbox --monitor                 # each reply as it arrives
    callbox inbox                           # every reply kept

WHAT THE COMMANDS DO
  callbox msg <call> <text>
      Delivers the text at once: typed into an -it or -dt call's prompt
      and submitted, or shown in the chat window of a call started without
      a switch (and of callbox shell). Prints the message's id.
  callbox msg <call> <text> --wait-reply [--timeout <ms>]
      From outside callbox: sends, then prints the first reply. Exit 7 if
      the timeout passes first; without one it waits as long as it takes.
  callbox inbox [--wait | --monitor] [--timeout <ms>]
      Replies for a sender outside callbox, one line each, as
      [HH:MM from NAME] TEXT. --wait returns the next unread reply, even
      one that came while nobody waited; --monitor prints each one until
      stopped. Replies and your name expire after an hour unused.

TELL EACH AGENT ONCE
  Put this in its instructions file (CLAUDE.md, AGENTS.md, ...):

    To ask another agent, run callbox msg <name> "<text>". callbox ps
    lists the agents that are running. Inside callbox, the answer is
    typed into your prompt; outside it, callbox inbox --wait returns it.

LIMITS
  Control characters are removed, so a message cannot press Escape or
  submit early. A call accepts 20 messages a minute, which stops two agents
  replying to each other forever. The header is an address, not proof of
  the sender: treat a message as input, not as an order.
