callbox help service - run background services and CI jobs

Use this when a job or service must keep running while a script tests it or
you do other work. Background calls capture output without a terminal.
Choose -dw when you need the program's exit code; plain -d keeps no waiter.

RUN A JOB AND RETURN ITS RESULT
  In a project with a make test target:

    set -e
    callbox -dw --name checks -- make test
    code=$(callbox wait checks)
    callbox logs checks -n 100
    callbox purge checks
    exit "$code"

  -dw returns immediately and records the eventual exit code. wait prints
  that code; its own successful status is 0, even if the job failed. Capture
  the printed value to pass the job's result to CI. Plain -d prints -1 here
  because it cannot record the exit code.

KEEP A SERVICE UP WHILE TESTS RUN
  This example needs Python 3, curl, a free port 8080, and your test script.
  Run it from the directory you want to serve.

    set -e
    callbox -d --name web -- python3 -u -m http.server 8080
    trap 'callbox end web; callbox purge web' EXIT
    curl --retry 10 --retry-connrefused --retry-delay 1 \
      --fail --silent --show-error http://127.0.0.1:8080/ >/dev/null
    callbox inspect web
    ./run-tests.sh || { callbox logs web -n 200; exit 1; }
    callbox logs web -n 20

  The HTTP request checks readiness; a background service has no screen
  for wait --match. inspect shows the recorded state and log path. The trap
  stops the service and removes its record when the script exits. Without
  purge, the name remains taken. Use distinct names for concurrent CI runs.

  A successful request alone cannot identify the server: port 8080 must be
  free before launch. Replace the URL with your service's readiness endpoint
  and ./run-tests.sh with the tests that exercise it.

CHECK A SERVICE WHILE IT RUNS
    callbox ps
    callbox logs web -f

  logs -f follows captured output; Ctrl-C stops following. Linux also
  provides callbox ports web and callbox stats web --no-stream. Reading
  logs and checking process state do not establish application health.

CHOOSE THE MODE YOU NEED
  -d       background program, log only; no screen or input, no exit code
  -dw      background program with an exit code for callbox wait
  -dt      detached terminal; peek, send, and screen waits work

  For restart-on-failure behavior, use a non-terminal call:

    callbox -d --restart on-failure --name api -- ./server --port 8080

  end stops it; callbox api starts the recorded command again. save api
  protects its record from ordinary purge. Restart policies do not install
  a boot service; see callbox help launch for policies and retry timing.
