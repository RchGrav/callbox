backmux help service - run background services and CI jobs

Run jobs and services in the background with output captured in a log.
Use -dw to record the program's exit code. A plain -d launch without --rm
or an active restart policy retains no waiter.

RUN A JOB AND RETURN ITS RESULT
  In a project with a make test target:

    set -e
    backmux -dw --name checks -- make test
    code=$(backmux wait checks)
    backmux logs checks -n 100
    backmux delete checks
    exit "$code"

  -dw returns immediately and records the eventual exit code. wait prints
  that code; its own successful status is 0, even if the job failed. Capture
  the printed value to pass the job's result to CI. Plain -d prints -1 here
  because it cannot record the exit code.

KEEP A SERVICE UP WHILE TESTS RUN
  This example needs Python 3, a free port 8080, and your test script.
  Run it from the directory you want to serve.

    set -e
    backmux -dt --name web -- python3 -u -m http.server 8080
    trap 'backmux end web; backmux delete web' EXIT
    backmux wait web --match 'Serving HTTP' --timeout 10s
    ./run-tests.sh || { backmux logs web -n 200; exit 1; }
    backmux logs web -n 20

  -dt gives the service a terminal, so wait --match sees its ready line:
  exit 0 once it shows, 8 if the server ends first (backmux wait web then
  prints its exit code), 7 at the timeout. -u keeps Python's output
  unbuffered, so the line shows at once. The trap stops the service and
  removes its record when the script exits; without purge, the name
  remains taken. Use distinct names for concurrent CI runs.

  A service that prints no ready line, or must restart when it fails,
  runs with no terminal instead (terminal processes cannot restart):
  start it with -d --restart on-failure and check readiness another way,
  such as curl --retry 10 --retry-connrefused --fail on its endpoint.

CHECK A SERVICE WHILE IT RUNS
    backmux ps
    backmux logs web -f

  logs -f follows captured output; Ctrl-C stops following. Linux also
  provides backmux ports web and backmux stats web --no-stream. Reading
  logs and checking process state do not establish application health.

CHOOSE THE MODE YOU NEED
  -d       background program, log only; no screen or input, no exit code
  -dw      background program with an exit code for backmux wait
  -dt      detached terminal; peek, send, and screen waits work

  For restart-on-failure behavior, use a non-terminal process:

    backmux -d --restart on-failure --name api -- ./server --port 8080

  end stops it; backmux recall api restarts its recorded command. save api
  protects its record from ordinary purge. Restart policies do not install
  a boot service; see backmux help launch for policies and retry timing.
