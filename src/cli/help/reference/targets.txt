backmux help targets - process names, IDs, and prefixes

  <target>          resolve in the current invocation context
  user:<target>     restrict lookup to the invoking user's store
  system:<target>   restrict lookup to the root-managed store

target = Backmux process ID, ID prefix, process name, or unique name prefix

The Backmux process ID is a 64-character hexadecimal identifier, distinct
from the operating-system PID. Full IDs address a record directly.
An exact process name takes precedence over an ID prefix. If neither
matches, a unique name prefix can select a process.

Name lookup considers the command's applicable states: end/kill select
running processes or Unknown processes with a console, logs selects records
with logs, inspect selects retained records, and purge selects removable
records. If several applicable processes match, the resolver lists candidates
and exits 6. Use a longer prefix or the full name.

Inbox targets require complete inbox names. msg, inbox, and monitor accept
those names; process-ID prefixes and user:/system: scopes apply to process
targets. An active inbox name cannot also name a process in the same store.
swap has its own pane lookup; see backmux help swap.

COMMAND ABBREVIATIONS
A unique command prefix is accepted, such as backmux li for backmux list.
Top-level resolution checks a full command name, a lone process name or ID
prefix, an executable, then command prefixes and lone process-name prefixes.
Multiple matches produce an ambiguity error (exit 6). Names followed by
arguments are treated as programs, not as requests to reconnect.

See backmux help system for store selection and permissions.
