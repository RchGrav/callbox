backmux help targets - names, ids, and the start of either

  <target>          resolve in the current context
  user:<target>     force user-local lookup
  system:<target>   force root-managed lookup

target = process id, leading id prefix, process name, or the start of a name

A process id addresses one process directly, always. A process name resolves to
the single process recorded under that name, narrowed by the verb: end/kill/logs
look at running or logged processes, inspect looks at retained records, and
purge looks at removable past process data. Failing a whole name or an id
prefix, the start of a name works when one process the command can act on has it
(backmux logs hel for helper). When more than one process matches, backmux lists
them and exits 6 - it never picks one.

Outside inboxes have names too. msg, inbox, and monitor accept an inbox's
complete name; process IDs, prefixes, and user:/system: scopes apply to
processes. An active inbox name cannot be assigned to a process in the same
store.

Verbs shorten the same way: backmux li is backmux list, when nothing else
has that meaning. The top-level word is tried in this order: a verb; a process
by whole name or id prefix (redial); a program on PATH; then the start of
exactly one verb or (alone) one process's name. Several fits are listed, exit 6.
