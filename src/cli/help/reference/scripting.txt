backmux help scripting - stdout, stderr, timeouts, and exit codes

Commands write results to stdout and status notes or errors to stderr.
--quiet suppresses normal status notes. Program output follows its launch
mode; terminal output can contain escape sequences and merged stdout/stderr.

  id=$(backmux -d PROGRAM)        capture the full Backmux process ID
  id=$(backmux -dw PROGRAM)       also retain the program's eventual exit code
  backmux end --print "$id"       print a SIGTERM command without executing it
  backmux kill --print "$id"      print a SIGKILL command without executing it

Exit codes:
  0    success, including a known process with no applicable action
  1    usage error or a failure without a more specific code
  2    action refused after identity or safety checks
  3    permission, console-access, or storage/security failure
  4    signal delivery failed
  5    no matching process or inbox, or invalid target syntax
  6    ambiguous command or process target
  7    wait, send --wait, inbox --wait, monitor, or reply wait timed out
  8    process ended or its console closed before a screen condition held;
       attach target ended; or an inbox expired while waiting
  9    send --mouse: mouse reporting disabled; mouse event not delivered
  10   target has no screen or input console
  11   requested name already belongs to a process or active inbox
  126  executable found but cannot be run
  127  executable not found

These are management-command statuses. A foreground launch propagates the
program's exit status when it finishes; detaching returns control while the
program continues. attach returns 0 on detachment and 3 on access failure.

For end or kill with multiple targets, each target is handled independently.
The command reports failures and returns the highest resulting exit status.

MESSAGE OUTPUT
msg to a process prints its delivery ID. A send to an outside inbox prints
no ID. --wait-reply prints the first new inbox message, from any sender.
inbox and monitor print [HH:MM from NAME] TEXT; message text may span lines.
The first generated inbox name and status notes go to stderr.

JOB RESULTS
An exit-only wait returns 0 when it observes exit and prints the recorded
program exit code separately. Capture that value to propagate a job's result.
Use -dw for background jobs that need an exit code; plain -d records none
and wait prints -1.

Unknown is a process state, not an exit code. wait continues until evidence
of exit or its timeout. Console commands can reach a broker even when its
program is not visible in the caller's process namespace.

TIMEOUTS
Screen waits and send durations accept milliseconds or ms, s, m suffixes.
Inbox, monitor, and msg reply timeouts accept whole milliseconds only.
--timeout 0 disables the timeout. Defaults differ by command; see its help.
