callbox help scripting - exit codes, stdout, and stderr

stdout is for machine data. Human banners, confirmations, warnings, and
errors go to stderr; --quiet suppresses normal human status.

  id=$(callbox -d <cmd...>)       capture the bare 64-hex call id
  id=$(callbox -dw <cmd...>)      ...and record its exit code for callbox wait
  callbox end --print <id>        print kill -TERM -- -<pgid>
  callbox kill --print <id>       print kill -KILL -- -<pgid>

Exit codes:
  0  success (includes known name with nothing to do)
  1  usage error (unknown option, bad value, wrong number of arguments), or a
     failure with no code of its own
  2  refused for safety
  3  permission denied, unavailable console, or storage/security failure
  4  signal delivery failed
  5  no matching call or inbox, or an invalid target id or name
  6  more than one call (or verb) matches: they are listed; be more exact
  7  wait, inbox --wait, monitor, or msg --wait-reply timed out
     (send --wait: input was sent; the program did not go quiet in time)
  8  the call ended: before the wait condition held (send --wait: after the
     input was sent), or (attach) before or while you were on it; attach
     exits 0 when you detach, 3 if refused or unreachable; an inbox can expire
     while waiting
  9  send --mouse: the program has mouse reporting off (not delivered)
  10 the call has no terminal screen or console (placed without -t / -i)
  11 the requested name is taken by a call or active inbox
  126 the command was found but cannot be run; 127 command not found

With several targets (end a b c), each is acted on alone: the ones that
resolve are ended, the rest reported, and the exit code is the worst.
callbox msg to a call prints its delivery ID. Sending to an outside inbox
does not print an ID. --wait-reply then prints the first new inbox message,
from any sender. inbox and monitor print [HH:MM from NAME] TEXT; messages
can span multiple lines. Status notes and the first inbox name go to stderr.

An exit-only callbox wait returns 0 on success and prints the program's
exit code. Capture that value to propagate a job's result; use -dw to keep
it, since plain -d has no exit record and wait prints -1.
If another environment cannot determine whether the call ended, its status
is Unknown. wait keeps waiting for evidence or --timeout; Unknown is not an
exit code. Console commands can still reach a broker whose process is not
visible here.

Screen wait and send durations accept milliseconds or ms/s/m suffixes.
Inbox, monitor, and msg reply timeouts accept whole milliseconds only.
--timeout 0 means no timeout; defaults differ by command.
