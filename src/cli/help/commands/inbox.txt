usage: callbox inbox [NAME] [--wait | --monitor] [--timeout MS]

Read replies for a sender outside Callbox. Its first callbox msg creates an
inbox and prints the generated name. With no NAME, use the current harness's
inbox; an explicit name reads that inbox from another terminal or harness.

  (no options)     print all retained messages, oldest first; mark them read
  --wait           print the first unread message and return; wait if empty
  --monitor        print unread messages, then follow new ones until stopped
                   (equivalent to callbox monitor)
  --timeout MS     bound --wait or --monitor in milliseconds
                   (0 = no limit, the default)
  -h, --help       show this page

Each message prints as [HH:MM from NAME] TEXT; text can span multiple lines.
All readers share the inbox's unread position. Reading history marks it
read too, so a later --wait waits for a new message.

The inbox name is based on the invoking harness process. A different
harness may have a different name; use the name printed by the first send
when crossing between them. Names expire after an hour without use.
Messages expire one hour after delivery, even if the inbox stays active.

Inside a call, messages arrive as program input or in chat; there is no
automatic outside inbox to read. Use callbox msg --received for that call's
delivery history. An explicit outside inbox NAME can still be read.

Exit status: 0 read successfully, 5 no such inbox, 7 timed out,
8 inbox expired while waiting. See callbox help messaging for a workflow.
